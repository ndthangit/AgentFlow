# Docker infrastructure for AgentFlow

AgentFlow uses a base Compose and two override files. This way keeps the service definition,
healthcheck, volume and dependency in one place, but still clearly separate how each runs
environment.

| Environment | Compose | Env | Default project |
| --- | --- | --- | --- |
| Local | `compose.yaml` | `.env` | `agentflow` |
| Server dev | `compose.yaml` + `compose.dev.yaml` | `.env.dev` | `agentflow-dev` |
| Production | `compose.yaml` + `compose.prod.yaml` | `.env.prod` | `agentflow-prod` |

Do not run `compose.dev.yaml` or `compose.prod.yaml` separately; they are overrides of
`compose.yaml`. The project name is different for the container, network and named volume of the three
environments do not overlap each other.

All commands below are run in the Docker directory:

```powershell
Set-Location docker
```

## 1. Local

Current local build source, just bind service to `127.0.0.1` and run Keycloak with it
`start-dev`.

```powershell
Copy-Item .env.example .env
# Change sample passwords before first run.

docker compose config
docker compose up -d --build
docker compose ps
```

Local endpoints:

| Service | Host URL/port |
| --- | --- |
| Web | `http://localhost:3000` |
| System API | `http://localhost:8000` |
| Keycloak | `http://localhost:8080` |
| Keycloak management | `http://localhost:9000` |
| PostgreSQL | `127.0.0.1:5432` |
| Redis | `127.0.0.1:6379` |
| Filesystem MCP | `127.0.0.1:8002` |

### Test provider does not need an actual API key

Compose override `compose.provider-mock.yaml` running local endpoint for OpenAI,
Anthropic and NVIDIA, and configure System API/worker to use that endpoint instead
Internet:

```powershell
docker compose `
  -f compose.yaml `
  -f compose.provider-mock.yaml `
  up -d --build
```

In Models UI, use `test-openai-key`, `test-anthropic-key` or
`test-nvidia-key`. Fake catalog returns `test-chat-model` to OpenAI/NVIDIA and
`test-claude-model` for Anthropic. This override is for local/CI only and is not available
combined with `compose.prod.yaml`.

### Enable local observability

The monitoring stack is an optional Compose override, including OpenTelemetry Collector,
Prometheus, Loki, Tempo, Alloy, Grafana and exporter for PostgreSQL/Redis:

```powershell
docker compose -f compose.yaml -f compose.langfuse.yaml -f compose.observability.yaml config
docker compose -f compose.yaml -f compose.langfuse.yaml -f compose.observability.yaml up -d --build
docker compose -f compose.yaml -f compose.langfuse.yaml -f compose.observability.yaml ps
```

| Service | URL local |
| --- | --- |
| Grafana | `http://localhost:3001` |
| Prometheus | `http://localhost:9090` |

Grafana uses `GRAFANA_ADMIN_USER` and `GRAFANA_ADMIN_PASSWORD` in the env file.
Datasource and AgentFlow dashboard are provisioned automatically. Stop stacking but keep data
data with the correct Compose file list and `down` command; only add `--volumes` when master
Automatically deletes telemetry data as well.

### Enable Langfuse local

Langfuse is the third override, using an existing Collector to selectively clone objects
workflow span to Langfuse. Tempo still receives the entire distributed trace; Langfuse pointed
Get run, node, Agent container and LLM observation marked.

```powershell
docker compose `
  -f compose.yaml `
  -f compose.observability.yaml `
  -f compose.langfuse.yaml `
  config --quiet

docker compose `
  -f compose.yaml `
  -f compose.observability.yaml `
  -f compose.langfuse.yaml `
  up -d --build
```

Open `http://localhost:3002`, log in with `LANGFUSE_INIT_USER_EMAIL` and
`LANGFUSE_INIT_USER_PASSWORD`. Project and API key are headless-init from
`LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY`; These keys are simultaneously collected by the Collector
used to ingest OTLP. Default values are for local use only. With server development or
production must change all passwords, salts, keys and `LANGFUSE_ENCRYPTION_KEY` first
when starting for the first time; `LANGFUSE_PUBLIC_URL` must be an HTTPS URL via reverse proxy.

Input/output is filtered for credential-like fields, limited by
`LANGFUSE_MAX_IO_BYTES`, then send. Set `LANGFUSE_ENABLED=false` to stop exporting data
workflow data; set `OPENINFERENCE_HIDE_INPUTS=true` and
`OPENINFERENCE_HIDE_OUTPUTS=true` to hide the payload generated by LangChain instrumentation
go out. When override is enabled, `LANGFUSE_TRACES_SAMPLER_ARG=1.0` ensures that all runs are taken
sample; production can reduce rates after locking in retention and capacity. `runs` and
`run_steps` remains authoritative business data.

Quick check:

```powershell
docker compose -f compose.yaml -f compose.observability.yaml -f compose.langfuse.yaml ps
docker compose -f compose.yaml -f compose.observability.yaml -f compose.langfuse.yaml logs --tail 100 otel-collector langfuse-web langfuse-worker
```

Stop local but keep data:

```powershell
docker compose down
```

## 2. Server development

Server dev still builds directly from source, but uses the public URL of the server and project
and private network, and limit Docker logs. PostgreSQL, Redis, MCP and gateways
Management Keycloak defaults to only bind loopback; web, API and Keycloak bind `0.0.0.0`
so you can test from another machine.

```powershell
Copy-Item .env.dev.example .env.dev
# Edit password, email and three variables WEB/SYSTEM/KEYCLOAK_PUBLIC_URL.

docker compose `
  --env-file .env.dev `
  -f compose.yaml `
  -f compose.dev.yaml `
  config

docker compose `
  --env-file .env.dev `
  -f compose.yaml `
  -f compose.dev.yaml `
  up -d --build
```

View status and log:

```powershell
docker compose --env-file .env.dev -f compose.yaml -f compose.dev.yaml ps
docker compose --env-file .env.dev -f compose.yaml -f compose.dev.yaml logs -f system workflow-worker
```

Stop the dev server:

```powershell
docker compose --env-file .env.dev -f compose.yaml -f compose.dev.yaml down
```

## 3. Production server

Production does not build source on the server. `compose.prod.yaml` completely eliminates `build`
and only pull immutable images declared in `.env.prod`. PostgreSQL, Redis and
Filesystem MCP does not publish port. Web, API, and Keycloak default bind loopback to
The reverse proxy on the host terminates TLS.

Prepare:

1. CI build and push four images `system`, `web`, `agent-runtime` and `filesystem-mcp`.
2. The web image must be built with the correct `VITE_SYSTEM_API_URL` and
   production `VITE_KEYCLOAK_URL` because these values are embedded at build time.
3. Reverse proxy maps HTTPS hostnames to:
   - web: `127.0.0.1:3000`;
   - System API: `127.0.0.1:8000`;
   - Keycloak: `127.0.0.1:8080`.
4. Create volume/database backups before each version upgrade.

Deployment:

```powershell
Copy-Item .env.prod.example .env.prod
# Replace all secrets, public URLs and images in .env.prod.

docker login ghcr.io

docker compose `
  --env-file .env.prod `
  -f compose.yaml `
  -f compose.prod.yaml `
  config

docker compose `
  --env-file .env.prod `
  -f compose.yaml `
  -f compose.prod.yaml `
  pull

docker compose `
  --env-file .env.prod `
  -f compose.yaml `
  -f compose.prod.yaml `
  up -d --remove-orphans
```

Post-deployment check:

```powershell
docker compose --env-file .env.prod -f compose.yaml -f compose.prod.yaml ps
docker compose --env-file .env.prod -f compose.yaml -f compose.prod.yaml logs --tail 200 system workflow-worker keycloak
```

Production Keycloak runs the command `start` with proxy headers instead of `start-dev`.
`agentflow-realm-prod.json` only allows redirection to `WEB_PUBLIC_URL`, not enabled
Direct Access Grant of CLI local.

## 4. Service and data

| Service | Responsibility |
| --- | --- |
| `postgres` | General database; Application data and Keycloak are in separate schema |
| `redis` | Redis Stream queue and pending jobs |
| `db-init` | Create idempotent schema `system` and `keycloak` |
| `keycloak` | OIDC, user and web client PKCE |
| `system` | FastAPI control plane, migration and outbox orchestrator |
| `workflow-worker` | Claim queue, execute graph and write run/step |
| `workflow-recovery` | Fail run loses heartbeat and recovers orphaned Agent container |
| `agent-runtime-default-image` | Build/pull the default Deep Agents image before the worker runs |
| `agent-runtime-codex-image` | Build/pull Codex CLI image before worker runs |
| `agent-runtime-opencode-image` | Build/pull image OpenCode SDK/server before worker runs |
| `agent-runtime-openhands-image` | Build/pull image OpenHands Software Agent SDK before worker runs |
| `filesystem-mcp` | MCP demo on private network runtime |
| `web` | React UI served by Nginx |

Named volume stores PostgreSQL, Redis, provider encryption keys, and MCP data. Command
`down` holds volume. Only use `down --volumes` when you really want to erase all data;
This operation cannot be undone.

## 5. Worker and Agent runtime

Number of workers configured with `WORKFLOW_WORKER_REPLICAS`. Replicas are shared
Redis consumer group but has its own consumer name, so one message can only be one
worker claim at a time.

The worker holds the lease in PostgreSQL and renews it according to `WORKFLOW_HEARTBEAT_SECONDS`.
If `WORKFLOW_LEASE_TTL_SECONDS` is too high, `workflow-recovery` switches to run/step running
to `failed` with code `WORKER_LOST`, then clear the container according to the label. Control cycle
configured with `WORKFLOW_RECOVERY_INTERVAL_SECONDS`. Outbox playback still shakes
`pending` after `WORKFLOW_OUTBOX_REDISPATCH_SECONDS`, so Redis restart or lose
Stream data without shaking is permanently stuck.

`WORKFLOW_TIMEOUT_SECONDS` (default 900 seconds) limits the entire runtime of
a workflow, independent of each Agent node's `AGENT_RUNTIME_TIMEOUT_SECONDS`.
Workers proactively cancel tasks/containers when they are overdue; recovery also hits `failed` with the code
`WORKFLOW_TIMEOUT` for run `pending` or `running` is suspended so the state cannot
lies indefinitely. The Stop button broadcasts Redis events to the correct worker, not polling the database;
Persistent commands in PostgreSQL are only read at subscribe/reconnect for protection
lost signal due to race or Redis reconnect.

Agent node selects image according to runtime id in `AGENT_RUNTIME_IMAGES` (`default`,
`codex` or `opencode` in the current stack). Provider, model and API key are obtained from Models and
The workflow has been registered and then temporarily injected into the container via contract
`AGENT_PROVIDER_*`; they are not in the deploy env file. Runtime Codex used
Responses API of the selected provider and does not use a personal Codex login account.
Runtime OpenCode starts the loopback server in the container, denying built-in tools, only
allow tool of the selected MCP and only use the selected OpenRouter provider/model for invocation.

Workers now need a Docker socket to create an Agent container:

```text
/var/run/docker.sock:/var/run/docker.sock
```

This permission is equivalent to Docker host administrative permission. Compose production has reduced surface area
public network but have not replaced Docker socket with an independent runner supervisor.
Before considering the system as hardened production, it is necessary to separate the runner to a separate host/node,
Limit image allow-list and use short-term credentials.

## 6. Keycloak realm

- Local uses `docker/keycloak/agentflow-realm.json`, including localhost redirect and CLI
  development.
- Server dev uses `docker/keycloak/agentflow-realm-dev.json`, gets redirect/origin from
  env and enable HTTP for testing.
- Production uses `docker/keycloak/agentflow-realm-prod.json`, gets redirect/origin from
  env and requires HTTPS for external requests.
- Import using `--override false`: only create realm if it does not exist. Can I change the JSON file?
  update realm in old volume; Please edit using Admin Console or create a new deployment.
- `KEYCLOAK_DEV_USER_ID` must be stable after the workflow is in place because claim `sub` is the key
  own data.
